# 复刻思路和过程

目标很具体：不是“做一支风格差不多的片子”，而是把参考片的骨架原样拿过来，包括镜头数量、每一刀落在哪、文字卡怎么出场、哪里放慢、哪里收尾，然后把内容整个换成另一个产品的真实功能。

下面按实际做的顺序写。参考片的逐镜头数据在 `reference-analysis.md`。

## 1. 把参考片拆到帧

**基本参数。** 先用 ffprobe 和 ebur128 量：1280×720，30 fps，99.80 秒，整体响度 −16.3 LUFS。左上角的 B 站水印不算设计的一部分。

**抽帧。** 全片按 5 fps 抽成 499 张，拼成 13 张联系表，用来通读节奏。再在每个镜头中间取全分辨率关键帧，共 32 张，用来看字体、配色和屏幕上的文字。这些图只留在本地，没有放进仓库。

**找剪辑点。** 用原生 30 fps、缩到 320×180，逐帧算平均亮度差。峰值同时超过 7、并且超过附近中位数 2.5 倍，就算硬切，这样找到 29 个。剩下的是软转场：打字后切、变焦模糊甩出、溶解、窗口从下往上升，帧差抓不到，只能对着 5 fps 联系表人工定时间，误差约 ±0.1 秒。镜头内部的小切（比如主题切换那段连切 7 下）用帧差精确定位。最后整理出 37 个镜头和 14 个镜头内小切。

**屏幕文字。** 逐张看关键帧，把每张文字卡和界面上的字抄下来，抄完再回到帧上核对一遍。核对时发现一个错：第 31 镜最初记成了「随心所欲」，帧上实际是「随心所愿」。全片没有旁白，只有音乐和 UI 音效。

**颜色。** 直接从帧上取色：
- 白色文字卡 #fdfdfd，层叠文字那张 #efefef；
- 正文 #131925 / #1a2333，强调蓝 #2c63c7；
- 开头流体背景 #223a59，结尾黑卡 #000、白卡 #fcfcfc。

界面基本是黑白灰，颜色只留给生成出来的内容和每张文字卡的后半句。

## 2. 节拍：110，不是 143.6

librosa 的 `beat_track` 直接给出 143.6 BPM，照这个去对剪辑点，怎么都对不齐。

换个办法：对每一段的 onset 包络做自相关，峰值落在 0.273 秒、0.819 秒、1.091 秒、2.183 秒。分别对应：
- 八分音符；
- 附点四分（3-3-2 的切分）；
- 二分音符；
- 一小节。

由此算出真实速度是 **110 BPM**：一拍 0.5455 秒，八分 0.2727 秒。用最强的几个 onset 拟合网格，起点偏移 0.030 秒。

143.6 的来历：3-3-2 的重音间隔是 0.819 秒，折算成速度大约就是 146，`beat_track` 被这个节奏型带偏了。

另外量出来的几处结构：
- 60–72 秒是半速段，主导间隔 1.637 秒，正好 3 拍；
- 75 秒左右全速回来；
- 92 秒开始音乐变薄，最后落在 logo 的一声「叮」上。

参考片的剪辑点和八分网格的平均偏差是 59 ms，只是“松散地”卡在拍子上。57–72 秒和 96–99 秒那几刀卡得最紧，偏差都在 35 ms 以内。

## 3. 网格对齐的时间线

两支片子共用同一套剪辑网格：每个镜头的入点取参考片对应时刻，再吸附到最近的八分音符。

```python
E = 60/110/2                       # 0.2727 s
s = lambda t: round(round(t/E)*E, 4)
```

`build/timeline.py` 是唯一的数据源，生成 `timeline.json`，里面有：
- 37 个镜头的起止时间（秒和帧，60 fps）、镜头内小切；
- 每段打字的起点和速度，删除的起点和速度；
- 点击、甩出、冲击、叮这些音效的时间。

Remotion 读它画画面，`audio.py` 读它放音效，所以改一处，两边一起变。

吸附后和参考片的偏差：最大约 0.13 秒，平均 50 多毫秒。和节拍网格的偏差 ≤ 8 ms（误差来自 60 fps 取整）。

## 4. 段落对位

参考片的段落和比例（占 99.8 秒的百分比）照搬，每个位置换上目标产品里功能相当的东西：

| 参考片 | 比例 | MosMos | MOSS Create |
|---|---|---|---|
| logo + 认识一下 | 6% | 官网 logo 像素拼合 | 官网 SVG 标志，背景是模板封面墙 |
| 功能名层叠 + 模式切换 | 7% | 「语音输入」层叠，按 Fn 唤起 | 「MOSS Create」层叠，打开 Auto / 专家 菜单 |
| 演示一（下班倒计时）+ 两张字卡 | 18% | 说话 → 润色 → 发出 | 点快捷生图标签 → 提示词填好 → MOSS Image 专区 |
| 演示二（便签墙） | 12% | 场景切换：邮件、文档 | 爆款模板库 → 使用模板 → 模板预览 |
| 递进问句 + 三个大演示 | 20% | 提示词、终端、会议纪要 | 音色库、早安电台语音合成、Agent 创作页 |
| 你来定义（换主题） | 8% | 润色三档 + 热词，明暗切换 | 浅色 / 暗色 / 英文界面，按参考片的 7 个小切翻 |
| 打字又删掉 + 都能实现 | 5% | 聊天、邮件 → 文档、终端 | 复古杂志封面 → 早安电台 |
| 快速蒙太奇 + 随心所愿 | 14% | 会议、待办、快捷键 | 真实模板预览视频；想到就做 |
| 主张句、打字后删的标语、logo 收尾 | 10% | 让文字，重新从声音开始 | 让灵感有声有色；和 MOSS Create 一起，把想法变成作品 |

文案原则：功能和用词都来自产品官网原文，比如“描述成图”“使用模板”“早安电台”“把想法变成作品”。串场的问句写短，写成人说话的口气，不编官网上没有的功能。强调色换成各自品牌的颜色：MosMos 是从官网纹理里取的蓝，MOSS Create 是网站按钮的绿 #005f4a。

## 5. 产品画面怎么来的

**MosMos。** 它是要安装的桌面软件，拿不到真实录屏。做法是：
- 照官网首页的演示组件重画：语音胶囊、场景标签、润色三档、热词卡、会议卡；
- 官网的 logo 和 ASCII 插画纹理直接用；
- 聊天、邮件、终端窗口画成通用的单色示意，不模仿任何真实应用。

**MOSS Create。** 能用真实画面就用真实画面。

1. **录屏工具。** Playwright 打开公开页面，通过 CDP 的 `Page.startScreencast` 录屏。截下来的 JPEG 时间戳不均匀，用 ffmpeg concat 清单按真实间隔拼起来，再转成恒定 60 fps 的 H.264（`tools/record.mjs`）。
2. **光标。** 往页面里注入一个假光标，用缓动曲线移动，看起来像人在操作。
3. **弹窗。** 两个登录推广弹窗按文字匹配后隐藏。
4. **懒加载。** 图片是懒加载的，正式录之前先把页面滚一遍。

几个绕不过去的限制：
- **登录墙。** 一点输入框就弹登录框，没法真的打字和生成。所以“输入”这一拍，用的是点快捷生图标签后提示词自动填满的真实画面，片子里也没有出现生成结果。
- **菜单打不开。** 录屏环境里 Auto 菜单怎么都点不开。最后从另一次截图里把菜单那一块像素裁下来，叠在干净的首页截图上，坐标完全一致。
- **模板悬停态。** 模板卡片的悬停状态（使用模板按钮）是照网站样式重画的，底下是真实封面。

**竖版是重新排版，不是加黑边。** 所有界面镜头都走同一个 `Stage` 组件。镜头参数写成“缩放 + 源画面里的焦点坐标”：
- 横版按这个参数推拉；
- 竖版用同一个焦点，裁出更窄、更大的区域，上方加一个小标签写明是哪个页面；
- 竖向的模板视频在竖版里直接铺满；
- 文字卡在逗号处断成两行。

MosMos 那支做得早，竖版还是“居中加模糊垫底”的做法。

## 6. 配乐和音效

全部用 numpy / scipy 合成（`audio/audio.py`）：
- 底鼓、拍手、踩镲、锯齿波贝斯、拨弦琶音、铺底和弦、噪声上升音、卷积混响；
- MOSS Create 版另加了正弦超低音、主旋律、沙锤、通鼓过门、镲片，铺底和弦跟着底鼓做“压缩呼吸”，再做一点立体声展宽。

结构对着参考片来：
- 110 BPM，3-3-2 的底鼓和贝斯；
- 半速段放在参考片同一位置（第 23 镜到第 26 镜之间）；
- 打字删除段做军鼓加速和上升音，冲进「都能做出来」；
- 蒙太奇恢复全速；
- 标语段只留铺底和闷鼓；
- 最后一声「叮」。

UI 音效全部挂在 timeline.json 的事件上：每个字一下键盘声、删除声、点击、甩出的风声、logo 出现时的故障声、切镜时很轻的嘀嗒。

母带处理：先 `alimiter` 限幅，再做两遍 `loudnorm`，第二遍用第一遍的测量值、线性模式，得到 −14 LUFS，真峰值约 −0.5 dB。

## 7. 检查流程

每次改完都过一遍：

1. **静帧。** `stills.mjs` 给每个镜头取 60% 处一帧，每个镜头内小切后面再各取一帧，横竖两版都取，拼成带镜头编号的大图逐张看：
   - 字体有没有变成方块；
   - 文字有没有溢出或换行错位；
   - 有没有空白帧；
   - 有没有漏出登录弹窗。
2. **规格。** ffprobe 核对分辨率、帧率、总帧数（5989）、时长。
3. **剪辑点扫描。** 对成片跑 ffmpeg `scdet`，和 timeline 里计划的 51 个剪辑点逐个匹配，命中的误差在 8 ms 以内。白卡切白卡、模糊溶解这类 scdet 抓不到的，在计划时间点前后取帧算差值，确认一帧之内确实变了。多抓到的几个点要逐个查原因，MOSS Create 版就有几个是模板预览视频自己内部的剪辑。
4. **响度。** ebur128 量整体响度和真峰值，再分段量 RMS，看半速段和蒙太奇的能量起伏是不是在对的地方。
5. **左右对比。** 参考片放左边、成片放右边，参考片的声音走左声道、成片走右声道，戴耳机看一遍，节奏有没有对上一听就知道。

## 8. 踩过的坑

- **自动节拍检测要复核。** 143.6 是 3-3-2 节奏型带出来的假结果。用自相关看几个间隔的比例关系，比相信单个数字可靠。
- **软转场要人工定时间。** 帧差只能找到一半左右的剪辑点。
- **同名文件会被缓存。** 查看工具对同名图片有缓存，每次裁图都换个新文件名，不然会看到旧图。
- **`networkidle` 会超时。** 网页一直有长连接，`networkidle` 等不到，改成 `domcontentloaded` 再固定等几秒。
- **模拟点击不一定生效。** `mouse.down/up` 有时触发不了菜单，换成定位元素后 `click()`；还不行，就退回用真实截图拼。
- **录屏前先确认页面状态。** 截图里有没有弹窗、图片加载完没有，比事后补救省事得多。
- **不要拿“风格接近”糊弄。** 每个镜头都在表里写清楚对应参考片的哪一镜、偏了多少毫秒、画面来源是真实录屏还是重画（见两个 shotlist）。哪里做不到就写出来，比如登录墙、没有生成结果、MosMos 界面是重画的。
